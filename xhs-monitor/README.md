# 小红书对标商品销量监控

监控小红书上**对标店铺**某个商品的公开展示销量（页面上的「已售 XX 件」），
自动记录每日快照、计算增量与趋势。

---

## 启动（一条命令）

```bash
cd /Users/weizhenliang/WorkBuddy/2026-10-19-11-31-05/xhs-monitor
NODE_PATH=/Users/weizhenliang/.workbuddy/binaries/node/workspace/node_modules \
PLAYWRIGHT_BROWSERS_PATH=/Users/weizhenliang/.workbuddy/binaries/node/workspace/browsers \
node server.js
```

启动后会打印三个地址：

```
本机:      http://127.0.0.1:7788
手机访问:   http://192.168.x.x:7788   (需在同一 WiFi)
```

**手机用浏览器直接打开那个 192.168 开头的地址即可**，页面已针对手机屏优化过。

### 自动采集（内置，不用配 crontab）

**服务运行期间，到点自动采集。默认每天 09:00 和 21:00 两次。**

点页面右上角 ⏰ 可改：

- 开关自动采集
- 采集时间（24 小时制，可添加多个）
- 是否启动时立刻采一次

页面上会实时显示「下次执行」和「上次执行」时间。

> **注意：电脑需要保持服务运行。** 关机、休眠、退出终端期间无法采集。
> 早上开机晚于 09:00？那天的自动采集会跳过，直接等下一个时间点。

| 定时设置 | 副标题里的「设置」 |

### 两个层级：全部看分组，点进去看商品

**「全部」= 分组概览**，不是把商品平铺。每行一个分组：

```
分组              商品      累计已售   今日增量  窗口增量  最近增量  价格      今日组内最热
iPad电容笔        1/1店     1,845      +1       +7       +3      ¥38.6    是梨想也的店 +1   明细 ›
古德猫铃          2/2店     2,197       0       -18      -20     ¥19.9~21.8 今日无增长      明细 ›
重力眼罩          1/1店    54,000       0        0        0      ¥17.8    今日无增长       明细 ›
```

一眼就能看出**哪个品今天在起量**，以及各组的价差。
点任意一行进入该组，看组内各店铺的横向明细。

最右列按 **今日增量** 排名，不按最近增量——后者只是相邻两次采集的差，跨 0 点会被平台
日切修正干扰（可能出现"最近增量是负的、今天其实卖得最好"）。今天全组都没涨就明说
「今日无增长」，不拿其它口径的数字凑一列。

**KPI 也按概览口径**：监控分组数、商品数与店铺数、**当前增量最大的组**、最近采集时间。
不再显示「最近一次增量 +1」这种混合数字——所有商品加在一起，不指向任何具体决策。

| 你在哪 | 看到什么 |
|---|---|
| 点「全部」 | 各组汇总对比（组维度） |
| 点某个组标签 / 组行 | 该组内各商品明细（商品维度）+ 组内对比条 |

### 主界面只读，改动都在「商品管理」里

主界面的组标签**只能切换查看**，不提供新建、改名、解散。
商品的删除、调组也都不在主界面——**避免看着数据时手滑改错**。

所有改动集中在「商品管理」：

| 页签 | 能做什么 |
|---|---|
| **组管理** | 新建分组、改名、解散 |
| **商品管理** | 添加商品、调整所属组、删除商品 |

### 危险操作都有二次确认

点「解散」「删除」「改名」不会立刻执行，而是先弹确认框，
把**将要发生什么、影响多少数据、能不能恢复**讲清楚：

```
解散分组
  分组名称    iPad电容笔
  组内商品    1 个
  涉及店铺    是梨想也的店
  历史记录    5 条
  ─────────────────────────
  这 1 个商品会变成「未分组」，商品本身和 5 条历史数据全部保留。
  分组只是分类，解散不会删除任何数据。
                  [取消]  [确认解散]
```

删除商品会明确警告**无法恢复**，并显示会连带删掉多少条历史记录。
确认按钮用红色区分，取消后回到原处，不会跳走。

## 分组：同品多店对比

**核心场景**：同一个商品，你同时盯好几家店卖得怎么样。

### 怎么用

1. 右上角「商品管理」→「组管理」页签 → **+ 新建分组**
2. 切到「商品管理」→ **+ 添加监控商品**，粘贴链接，选择归到哪个组
3. 加第二个店铺的同类商品，同样归到这个组
4. 回到主界面，点顶部那个组的标签，就看到**组内各店铺横向对比**

### 组视图里有什么

**三层结构：分组 → 店铺 → 商品。** 因为竞品对比看的其实是「店」，
商品只是店里的货——一家店卖多个同类商品时，这家店本身也要有汇总。

```
▼ 是梨想也的店   3 个商品        2,460    +60    ¥35~¥42
    电容笔·紫蓝拼色                1,030    +30
    电容笔·粉色                      820    +20
    电容笔·白色                      610    +10
▸ 猫屿杂物集的店  1 个商品        1,705     +5    ¥45
    电容笔·平替款                  1,705     +5
```

| 层级 | 显示什么 |
|---|---|
| **店铺行** | 店铺名（字号更大）+ 商品数徽标 + 店铺累计 + 店铺增量 + 店铺价格区间 |
| **商品行** | 缩进显示，商品名 + 该商品累计/增量，右侧「补录 / 历史」 |

**店铺名优先、信息更重**：店铺行字号 13px 加粗，商品行 12px 常规并缩进 26px。

- 一家店有 **≥2 个商品**时才显示折叠箭头，点店铺行可折叠
- 只有 1 个商品的店铺不显示箭头，避免误导
- 店铺按**增量降序**排列，谁在跑一眼看到

### 组内对比也是店铺维度

右侧「店与店对比」条形图按店铺聚合，**每家店只出现一次**，
条长 = 该店在组内的累计占比，附店内商品数和价格区间。

组视图里点店铺行可以折叠 / 展开该店的商品。

### 排行与走势：都先看店铺，再看商品

**今日增量排行**（分层，点开才展开下层）

| 视图 | 默认排行 | 点开后 |
|---|---|---|
| 全部 | 按**分组** | 点分组 → 展开该组各店铺 |
| 组内 | 按**店铺** | 点店铺 → 展开店内各商品（只有 1 个商品的店不显示箭头） |

**累计走势**（多折线，一家店一条线）

| 视图 | 下拉框 | 图里画什么 |
|---|---|---|
| 全部 | **分组**（没有「全部」选项，默认选今日增量最多的组）+ **店铺**（默认全部店铺） | 该分组各店铺，一店一线 |
| 组内 | 只有**店铺**下拉（默认全部店铺） | 该组各店铺，一店一线 |

选中某个具体店铺后：店内**每个商品各一条线**，再加一条「店铺汇总」。
店内只有 1 个商品时只画那一条，**不重复画汇总线**。

**实际卖价走势**（只在组内显示，全部视图不出现）

组内所有店铺的所有商品画进**同一张阶梯图**，标签规则：

| 情况 | 标签 |
|---|---|
| 店内多商品 | `店铺短名·商品短名`（都会截断，不会长到挤爆图例） |
| 店内单商品 | 只显示店铺名 |

### 改名前 / 解散 / 调组 都在商品管理里

主界面不提供这些操作，避免误点。进「商品管理」→「组管理」：

- **改名**：点该行的「改名」，输入新名字 → **下一步** → 确认
- **解散**：点该行的「解散」→ 看影响说明 → 确认
- **调整商品分组**：「商品管理」页签里点「调组」

表格里的组名标签可以点击，直接跳到该组查看。

### 解散分组时，商品去哪了

**默认不会删任何商品**，只改变归属。解散时有三条路可选：

| 你的选择 | 结果 |
|---|---|
| **归到「未分组」**（默认，推荐） | 商品的 `group` 清空，出现在「未分组」标签下，数据全留 |
| 并入另一个组 | 商品直接并入你选的那个组，省得解散后再逐个归组 |
| ⚠ 连同商品一起删除 | **商品和全部历史记录彻底消失，不可恢复** |

前两条只销毁「分组」这个分类，商品、销量、价格、历史记录原样保留。
第三条是**真正的删除**，和「商品管理」里删单个商品一样，不可逆。

确认框会先把影响列清楚：

```
解散分组
  分组名称    iPad电容笔
  组内商品    1 个
  涉及店铺    是梨想也的店
  历史记录    5 条
  组内这 1 个商品怎么处理
    [归到「未分组」（推荐，数据全部保留）
     并入「古德猫铃」
     ⚠ 连同这 1 个商品一起删除]
  ──────────────────────────────────
  默认只改变分组归属：商品本身和全部历史数据都会保留…
                    [取消]  [确认解散]
```

**选了「一起删除」会怎样**：立刻出现红色警告块，说明将删掉几个商品、
多少条历史记录；确认按钮文案变成「继续（还有一步确认）」。
点下去后还会**再弹一次最终确认**，逐个列出要删的商品名、店铺、记录数，
并提示「如果只想让它们不在这个分组里，请取消并改选归到未分组」。

**两道确认都过了才会真删。** 任何一道取消，数据一条不动。

> 危险等级对比：
> **解散分组（前两个选项）= 安全的，数据都留**
> **解散分组（第三项）/ 删除商品 = 不可恢复**

表格里的组名标签可以点击，直接跳到该组查看。

## 核心要点

**真正有用的是增量，不是累计值。**

看演示数据就明白：

**双通道采集，免登录可用**

| 通道 | 触发条件 | 需要登录 |
|---|---|---|
| **公开 JSON 接口**（默认） | 一直走这个 | **不需要** |
| 浏览器页面采集 | 仅接口失败且本地有登录态时回退 | 需要 |

免登录接口实测：连续 23 次请求全部 HTTP 200，零风控，数值稳定。

**只需粘贴链接，其余全自动**

添加框支持三种粘贴方式，都直接扔进去就行：

| 粘贴内容 | 处理方式 |
|---|---|
| 商品详情页长链 `xiaohongshu.com/goods-detail/…` | 直接解析 |
| 分享短链 `xhslink.com/m/…` | 跟随跳转拿到真实商品 ID |
| **App 分享出来的整段文案** | 自动抠出链接，忽略口令码与引导语 |

整段文案长这样也能用：

```
【小红书】猫咪磁吸风铃冰箱贴 😆 nvJRp7r2K6 😆 https://xhslink.com/m/4T71eJQIwpB 点击链接或者复制本条信息打开【小红书app】查看 CZ6526
```

粘贴后输入框下方会立刻显示「✓ 已识别链接 xhslink.com/m/4T71…」，
没找到链接会直接标红提示，不用点了添加才报错。

添加时只填链接，工具自动识别并写入：

- 商品名称（取 `descriptionMain.name`，干净无规格后缀）
- **店铺名称**（`sellerH5.name`）与店铺主页链接
- 店铺销量、粉丝数、价格
- 并立即建立销量基线

实测样例：

```
输入: https://xhslink.com/m/F3UDAwqnJW
  商品: 【前2000单六折】防误触彩色马卡龙电容笔适用苹果ipad磁吸手写笔
  店铺: 是梨想也的店（已售1779，粉丝1637）
  价格: ¥78.6   基线: 1805
```

```
输入: 【小红书】猫咪磁吸风铃冰箱贴 😆 nvJRp7r2K6 😆 https://xhslink.com/m/4T71eJQIwpB 点击链接…
  商品: 【森之物】猫猫响叮当磁吸风铃盲盒·可爱猫咪冰箱贴·闺蜜礼物
  店铺: 贝贝xww的店   到手价: ¥21.8   基线: 556
```

> 名称以接口返回为准，分享文案里的短标题只作兜底。
> **去重按商品 ID 判断**——同一商品用短链、长链、分享文案分别添加，都会被认出来是同一条。


**真正有用的是增量，不是累计值。**

页面同时给三个增量，口径不同，别混用：

| 指标 | 算法 | 用来判断 |
|---|---|---|
| **今日增量** | 最新已售 − 今天 0 点前最后一次已售 | 今天卖得怎么样（主看这个） |
| **近 N 天增量** | 窗口内首尾两条有效快照相减 | 这一段时间的趋势 |
| **最近增量** | 相邻两次采集相减 | 刚才这一小段有没有动静 |

今天还没采集时，「今日增量」显示 `—` 而不是 `0`——`0` 会让人误以为「今天没卖出去」。
跨午夜也照常算：昨天 21:00 采到 1000、今天 09:00 采到 1030，今日增量就是 **+30**（夜间也在卖）。

一个真实例子：某商品累计 1850，**今日 +12，但最近一次只有 +5**——如果只看「最近增量」，
会漏掉今天早些时候已经卖掉的 7 件。这就是为什么要以今日增量为主。

**累计值会骗人**——所以页面以增量为主，KPI 也以增量为主。

其他设计：
- **失败记录不污染增量**：采集失败（商品不存在/不公开销量/风控）不入库
- **数字回退自动拦截**：退款、链接变更、口径调整会标红 `回退`
- **确定性结论不做无谓回退**：「商品已下架」不会再去开浏览器重试
- **手动补录与自动采集混用**：需要时可人工介入，数据不断档

## 价格：只看到手价

小红书商品页有两个价，含义完全不同：

| 字段 | 含义 | 可信度 |
|---|---|---|
| `highlightPrice` | **划线价**，商家可随意标高做对比 | 低，别用它判断 |
| `dealPrice.price` | **到手价**，减去商家券/立减后的实付价 | **高，这才是商家真想卖的价** |

工具采的是**到手价**。示例：

```
电容笔   划线价 ¥78.6  −  立减 ¥40  =  到手价 ¥38.6
猫猫盲盒  划线价 ¥39.9  −  立减 ¥20  =  到手价 ¥19.9
```

页面会显示：到手价（大字）、划线价（删除线）、直降金额、优惠名称与有效期。

### 价格阶梯图

**按变更日绘制**，不是按天连点。价格不变时是水平线，变更当天垂直跳变：

```
¥24.9 ┤                    ┌──────
      │                    │
¥19.9 ┤────────────────────┘
      └────┬────┬────┬───┬─┴──────
         10/1  10/6 10/13 10/19
```

对应你说的场景：11 号 10 块就一直画 10 块，20 号改成 15 块就在 20 号那天跳上去——
中间那些天不会画成一堆 10 又 15 的折点。

图下方还有**变更记录列表**：日期、从多少到多少、涨跌幅、当时的优惠活动。

涨价标红 ↑，降价标绿 ↓。

> **一张图看全组**：组内每个店铺的每个商品都画在同一张阶梯图上，图例右侧显示各自的当前到手价。
> 只有一个商品时才展开变更记录明细——多个商品时明细太长，看线就够了。
> 「全部」视图不显示这张卡，因为各组价格不可比，放在一起只会误导。

**注意**：只有实际采集到价格之后才会有价格曲线。工具早期采的是划线价，
为避免出现假的跳变，那些历史记录已标记为「未采集价格」，不会画进图里。

## 数据口径（重要）

**这里记的「累计已售」是商品页对访客公开显示的数字，不是真实订单量。**

会有这些偏差：
- 退款导致数字回退
- 平台展示延迟（不是实时）
- 平台口径调整
- 商品链接更换 / 下架

所以：

- ✅ 适合判断趋势、比较竞品节奏、发现起量品
- ❌ 不能当财务报表，不能拿来算竞品利润，不能对外声称是对方真实销量

工具会在采集到数字回退时自动标记 `suspicious`，并在看板上写明口径。

## 合规说明

- 只读取页面公开可见内容
- 不修改任何原始数据
- 不绕过平台技术保护措施（不逆向签名、不破解登录）
- 不模拟虚假互动

厦门中院 2026 年典型案例确认：**不突破技术保护措施 + 不改变数据原始状态 + 不妨碍平台运行**
的数据使用，属于「公开数据的合理使用」，不构成不正当竞争。

反例是修改文件 MD5 规避平台查重、为数据搬运提供便利——本工具不涉及此类行为。

采集频率建议保持在每天 1 次这种人类浏览量级，不要开成高频轮询。

## 常见问题

**采集失败提示「登录态失效」**
重新跑 `node xhs_monitor.js login` 扫码登录即可。登录态过期是常态。

**提示「页面未出现销量字段」**
可能该商品页本来就不显示销量，或者页面改版了。
打开链接人工确认一下——如果人工也看不到，这个商品就不适合监控，
改用 `record` 手动补录，或者换个商品。

**数字回退标成「回退」**
大概率是链接换了或平台调整了口径。检查一下商品是否还在原链接。

**采集会不会被风控？**
每天 1 次的低频采集风险很低。工具已内置请求间隔（默认 4 秒）。
不要把间隔调到 0，商品多的时候手动分批跑。
